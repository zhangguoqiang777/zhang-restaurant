# 小张的餐厅 · 微信小程序端

原生微信小程序 + TypeScript 实现，覆盖客户、商家、超级用户三类权限。视觉规范取自 `prototype/`，接口与数据模型对齐 `docs/架构与数据模型.md`。

本期不包含：价格金额、支付、库存、取餐、桌号、中英文切换、AI 推荐。

## 1. 在微信开发者工具中打开

1. 打开微信开发者工具，选择「导入项目」。
2. 项目目录选择本仓库下的 `miniprogram/`（不是仓库根目录）。
3. AppID 使用测试号占位：`project.config.json` 中当前为 `wxd669baa949752f7c`；如有自己的测试号，替换该字段即可。
4. 确认导入后直接编译运行，无需 `npm install`、无需构建步骤。

已配置：

- `useCompilerPlugins: ["typescript"]`，开发者工具会直接编译 `.ts`。
- `urlCheck: false`；若仍在真机/工具中请求失败，请在「详情 → 本地设置」勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
- 开发期默认连接本机 `http://localhost:3000`，请先启动 `server/` 后端；真机调试时把 baseUrl 改成电脑局域网 IP（如 `http://192.168.1.10:3000`），并确保手机与电脑同网。
- 测试号无法使用 `wx.login` 的真实 code 换取正式用户时，后端在开发环境提供 mock 登录：未配置 `WECHAT_APPID` 时，开发者工具的真实 code 固定映射为 `mock_dev`；显式传 `mock_zhang` / `mock_wang` 等 code 可得到不同测试用户（见「联调结果」与 `docs/联调报告.md`）。

## 2. 配置 baseUrl 与 appid

### baseUrl

- 默认值：`http://localhost:3000`，定义在 `api/config.ts` 的 `DEFAULT_BASE_URL`。
- 运行期可改：客户/商家/管理员「我的」→「接口地址」→「修改接口地址」，填写 `http://` 或 `https://` 开头的地址，重启页面后生效；也可「恢复默认」。
- 只填协议 + 域名 + 端口，不要带 `/api/v1`；请求层会自动拼接。图片按 `{baseUrl}/uploads/{image_key}` 拼接。

### appid

- 占位：`project.config.json → appid` 当前为测试号 `wxd669baa949752f7c`，可直接替换为自己的测试号。
- 换成自己的测试号时，同时确认后端 `WX_APPID` / `WX_SECRET` 与该 appid 一致。

## 4. 权限、tabBar 与守卫

- 原生 tabBar 要求 tab 页在主包，与分包结构冲突，因此使用自定义组件 `components/tab-bar`，按 `merchant` 属性渲染 4 或 5 项，切换用 `wx.reLaunch`。
- tab 组成：
  - 纯客户：点餐 / 订单 / 日历 / 我的
  - 有商家权限（`canMerchant`）或超级用户（`isSuper`）：点餐 / 订单 / 日历 / 管理 / 我的
  - 超级用户与商家 tab 相同，区别在「管理」页额外出现「用户授权」入口
- 三种身份实际可见范围：

| 身份 | tab | 「管理」页入口 | 其他可访问页面 |
|---|---|---|---|
| 纯客户 | 点餐、订单、日历、我的 | 无 | 菜品详情、购物车、订单详情、评价 |
| 商家（`canMerchant=1`） | 点餐、订单、日历、管理、我的 | 订单看板、采购清单、菜品管理、新增菜品、食材库 | 以上全部客户页 + 订单处理、菜品编辑 |
| 超级用户（`isSuper=1`） | 同商家 | 同商家 + 用户授权 | 同商家 + 用户授权页 |

- 权限刷新：点餐、订单、日历、我的、管理页在 `onShow` / 下拉刷新时调用 `GET /me` 校准权限，tabBar 随 `hasMerchant` 即时增减。
- 权限失效：失去商家权限时，管理页提示并自动 `reLaunch` 回点餐；商家子页在 `onShow` / 下拉刷新时重新校验，无权限静默回到可访问页面，不展示 403 或空白页。
- 直接通过路径访问商家/超管页面时，由 `utils/role.ts` 的 `guardManage` / `guardAdmin` 拦截并跳回点餐或管理页；后端仍逐请求校验权限。

## 5. 登录与持久化

- 启动时 `wx.login` 取 `code`，调用 `POST /auth/wx-login` 换 token。
- token 存本地缓存（`wx.setStorageSync`，键 `zhang_token`），用户信息缓存 `zhang_user`，重启后仍是同一用户。
- 请求层自动注入 `Authorization: Bearer <token>`；401 时自动强制重登一次并重试原请求，仍失败则回到点餐页。
- 网络失败但本地仍有登录态时，页面回退缓存用户展示，不会直接清空登录。

## 6. 已实现的交互（后端启动后即可跑通）

- 客户：进入即点餐 → 菜单加购 → 购物车改数量/备注 → 提交订单 → 订单详情看状态 → 取消待处理订单 → 对已完成订单打分评论 → 日历切月份/切日期看订单。
- 商家：底部「管理」→ 订单看板按日期筛选 → 开始制作 / 完成制作 → 订单处理继续推进或取消 → 采购清单按日汇总 → 菜品搜索/筛选/上下架 → 分类新增/改名/启停/排序 → 菜品新增/编辑/图片上传/食材多选/新建食材 → 食材库新增/改名/启停。
- 超级用户：管理 → 用户授权 → 搜索用户 → 开关商家端权限（自己和超级用户禁用）→ 即时刷新状态。
- 被授权/撤销的用户重新进入页面或下拉刷新后，底部 tab 与「管理」入口随之出现或消失。
- 订单列表、看板、商家详情每 30 秒轮询，离开页面自动停止；支持下拉刷新。
